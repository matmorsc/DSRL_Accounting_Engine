# Deposit Draft Generator

## Purpose

The Deposit Draft Generator is read-only.

It does not connect to QuickBooks and does not create accounting transactions.

It converts payouts marked `generate_entry = Yes` into:

- one summary row per payout, and
- the proposed QuickBooks split lines for that payout.

## Inputs

Generated by the existing pipeline:

- `data/processed/posting_status.csv`
- `data/processed/payout_ledger.csv`
- `data/processed/payment_ledger.csv`
- `data/processed/reservations.csv`

Configuration:

- `config/deposit_draft_rules.yaml`

## Outputs

- `data/processed/deposit_drafts.csv`
- `data/processed/deposit_draft_lines.csv`

## Safety Gates

A draft is `Ready for Review` only when:

- the payout is eligible for entry,
- assigned payment events exist,
- payment events link to reservations,
- required account and class mappings exist,
- and proposed split lines equal the bank deposit within tolerance.

Anything else is `Review Required`.

## Current DSRL Treatment

- One draft per processor payout / bank deposit.
- Revenue is assigned to the reservation's configured income account.
- Classes use DSRL QuickBooks names:
  - Cabin -> Cabins
  - RV -> RV Sites
  - Motel -> Hospitality
- Direct Stripe taxes are posted to `Sales & Lodging Taxes Payable`.
- Stripe fees use `Bank Charges & Fees:Stripe Processing Fees`.
- Airbnb marketplace-remitted taxes are excluded.
- Airbnb fee account is intentionally unconfigured until Matt confirms the exact
  QuickBooks account name.

## Run

```powershell
python run.py
python build_deposit_drafts.py
```

The first command refreshes the accounting pipeline. The second builds drafts.
